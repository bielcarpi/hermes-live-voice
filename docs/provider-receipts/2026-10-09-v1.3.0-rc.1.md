# v1.3.0-rc.1 qualification

Date: 2026-10-09. Result: **release candidate; live voice qualification incomplete**.

This release simplifies the Dashboard and setup, defaults OpenAI to server VAD,
and fixes task selection, completion delivery, microphone cleanup, reconnect,
and retained-result retrieval. It publishes to npm `next`; v1.2.0 remains stable.

## Automated evidence

- Full verification passes 771 tests in 42 suites on Node 22.23.3. The full test
  suite also passes on Node 24.21.0.
- Node 20.20.2 packed-install checks pass, including activation and Zod 3/4
  consumers. Package, plugin, and Dashboard versions match.
- TypeScript, script syntax, documentation links, plugin/Python contracts,
  CLI/gateway fixtures, installed-package behavior, asset synchronization,
  and immutable workflow action pins pass.
- Docker builds and starts as its non-root user. Private-checkout asset
  permissions are handled; its task-state directory stays private.
- Dependency audit reports zero vulnerabilities.
- Real React Dashboard tests use the packaged browser SDK and a fixture
  WebSocket server. They cover chat selection, transcript isolation, request
  correlation, deduplication, failed-read retry, and full retained output.
- The actual OpenAI adapter is composed with the gateway, supervisor, and
  task store against external-service fixtures. VAD, dispatch, continued
  PCM, completion speech, and client audio delivery pass.

## Browser and Hermes checks

Chromium at 1440×1000 and 390×844 passed connect, synthetic microphone capture,
pause/resume, interrupt without task cancellation, exact task stop, reconnect,
and one fetch of a full 16,847-character result. No page errors or horizontal
overflow were observed. Screenshots are fixture previews.

Official Hermes images v0.20.0 (pinned) and v0.21.6 (current on the review date)
passed capability, plugin discovery/version, Dashboard route/backend, and
WebSocket authorization-helper checks. These checks start actual Hermes and
inspect its API; they do not establish a real model-backed worker result.
The image harness now makes the copied public plugin readable independently
of host checkout permissions.

## Live attempts and limits

OpenAI and Gemini functional checks were attempted but could not start:
this personal test environment has no provider credentials configured.
`launch-check` reported failed runtime readiness; no real Hermes worker is
configured for that deployment. These outcomes are blockers, not passes.

Physical microphone/speaker audio, acoustic interruption, perceived latency,
and a complete hosted-provider conversation remain unqualified. Historical
local-provider receipts describe earlier versions and hardware/load conditions.

Before a stable release, repeat the [end-to-end procedure](../live-provider-testing.md)
with real Hermes and a hosted provider: converse while work remains active,
interrupt, detach/reconnect, receive spoken completion, retrieve the full
result, stop an exact task, and reconcile a gateway restart.

Voice detachment preserves task execution. Gateway restart reconciles with
the same Hermes process; Hermes restart does not recover in-progress work.
Ambiguous dispatch remains fenced as unknown. OpenAI notices are out of band;
Gemini notices are best effort. Interactive approvals remain unsupported.
