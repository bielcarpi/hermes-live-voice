# v1.3.0-rc.2 UI qualification

This release replaces the plugin’s separate chat page with a slot inside Hermes’s supported web Dashboard. Provider defaults and the gateway protocol are unchanged from rc.1. This is a UI qualification, not a live provider receipt.

## Evidence

- Full `npm run verify`: 771 tests in 42 suites, type checking, Dashboard asset/auth/relay tests, plugin activation, local runtime contracts, CLI checks, gateway smoke, and packed-package consumer/installation checks passed.
- Official Hermes Agent v0.20.0 and v0.21.6: plugin discovery, hidden route, `chat:top` manifest, private bridge capabilities, and authenticated Dashboard helpers passed.
- Official Hermes v0.21.6 Dashboard in Chromium: the host loaded the plugin through its real manifest/registry. Native Chat, session list, terminal, navigation, and theme remained the rendered interface. The plugin used host SDK components and the real authenticated Python WebSocket relay.
- A fixture gateway and synthetic microphone verified capture, pause/resume, interruption without task stop, exact native-chat binding, automatic detach on chat switch, reconnect to the newly selected chat, end voice, and a 16,847-character retained result fetched once.
- Desktop 1440 × 1000 and mobile 390 × 844: no page errors or horizontal overflow. The README screenshot comes from this actual Hermes Dashboard with fixture data.

## Limits

The Dashboard plugin SDK exposes page slots and UI primitives, but no active unsaved PTY-session identity or API for streaming external messages into the TUI. Voice therefore starts after selecting a saved conversation in Hermes’s native list. External Hermes turns are persisted and load when the conversation is reopened. No private DOM/React inspection, PTY injection, host patch, or duplicate chat renderer is used.

Hosted provider credentials and physical audio devices were unavailable. Their qualification remains outstanding as recorded in [rc.1](2026-10-09-v1.3.0-rc.1.md). Keep this release on npm’s `next` channel.
